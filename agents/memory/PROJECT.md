# CityBalance project facts

## Approval and purpose
The user approved CityBalance, original logo direction and the complete proposed scope, then requested this executable plan. Approved Russian slogan: **«Решайте, каким станет город.»** The shorter slogan replaces all earlier drafts. No further concept or plan approval is required.
HackAlem is the event; SoloVibe is the team; CityBalance is the product. Name/domain/trademark uniqueness has not been claimed.
The selected case is «Аким на 5 часов». Exact case requirements, separate general/case rubrics, dataset and verified arithmetic are in [HACKATHON](../knowledge/HACKATHON.md). The case rubric is25/25/25/15/10; do not merge it with the general rubric.
User resolved the rule ambiguity: dataset rules govern, budget100, exactly5 distinct measures, <=2/direction and therefore >=3 directions. All-five coverage is an optional constraint.
Target users are municipal analysts preparing options and facilitators/teams rehearsing city-budget decisions. Practical value: compare feasible portfolios, preserve commitments, expose tradeoffs and carry a reasoned choice into discussion. Synthetic effects are not real-city forecasts or measured financial savings.

## Distinctive mechanism
The strongest defensible advantage is the observable price of a user priority, not an optimizer button or a large score.
The bounded concept challenge found that a finite catalogue can be solved once; a purely decorative city/AI commentary would add little. The approved implementation deepens the same job through locked commitments, exact substitutions, evidence, sensitivity repair and editable reusable decisions.
First-viewport proof: requiring direct investment in two districts changes the exact portfolio from cost98/Score57.236735 to cost100/Score56.997700, a0.239035 concession. Three measures stay; two change and affected districts are visible. Numbers come from production calculation; any optimum claim requires actual complete search.
A meaningful first session yields a saved feasible scenario/alternative and an inspectable explanation within a measured five-minute target. Landing start preserves the selected proof; the supplied95-unit source example is also immediately available. Guest work is persistent and claimable by an account.

## Prepared architecture and planned contracts
Existing Next.js App Router/React/TypeScript, Drizzle/PostgreSQL17, Better Auth, next-intl, AI SDK/OpenAI Responses and private R2/local storage are reused. Exact versions and commands: [STACK](../knowledge/STACK.md). Local app3000, PostgreSQL15432.
Public deployment origin: https://solovibe-5k5wvv7zo.gobrev.dev through Brev Secure Link/Nginx. [SETUP](../ops/SETUP.md) governs exact source-build SSH/manual deploy. No deployment was performed in planning.
OpenAI model stays configured by OPENAI_MODEL, default gpt-6-luna/default service tier. Missing key fails only the AI action; no fake answer or lost input.
A pure deterministic evaluator/search provides official numbers and constraints. AI receives current authorized records, evidence and tool observations, performs real adaptive operations, and saves checked alternatives/briefs. Prompt procedures/tools/quality examples are specified in stage01 and extended in02/03.
PostgreSQL stores owner/scenario/revision/evaluation/search/stress/run/brief/share state. A planned same-image worker handles durable jobs, with leases/fencing/receipts/heartbeat and app+worker revision checks. Prepared provider wrappers are not yet a working harness.
Private R2 or persistent local volume stores generated HTML/JSON/CSV bytes; PostgreSQL stores version/owner/checksum/key metadata. Authorized app downloads permit immediate revocation on new requests; deletion uses durable tombstones. No R2 means local functionality, not an in-memory substitute.
Guest principals use secure HttpOnly hashed-token ownership and30-day inactivity retention; accounts claim stable owner records without moving objects. Source revisions and brief versions prevent stale AI/edits from overwriting work.
Canonical cross-stage contracts/API/limits/data paths and acceptance are in [PLAN C1–C9](PLAN.md). Shared domain code now exists in src/features/city/; owned services and worker follow in01.2/01.3.
