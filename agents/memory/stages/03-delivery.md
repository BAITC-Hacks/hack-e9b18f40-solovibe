## 03.1 A usable, editable decision brief
Outcome: a chosen scenario becomes a defensible decision artifact; corrections survive AI updates and lead back to the exact source.
Paths: src/features/city/brief/{contracts.ts,components/,render.ts}; src/server/city/{briefs.ts,ai/prompts/brief.ts,ai/tools.ts}; src/app/[locale]/city/[id]/{brief,present}/page.tsx; /api/city/briefs/; schema/migrations/messages.
Entity: city_briefs {id,ownerId,scenarioId,sourceRevisionId,stressId?,comparisonRevisionIds[],version,title,locale,sections,sourceHash,status}. Section structure stores typed generated blocks/evidence references separately from user-authored text and user-edited flags. Never accept arbitrary model HTML.
API: POST /briefs {sourceRevisionId,stressId?,comparisonRevisionIds<=2,clientMutationId}; GET /briefs/:id; PATCH /briefs/:id {expectedVersion,sectionEdits}; POST /briefs/:id/refresh {expectedVersion,targetRevisionId,sectionIds?,clientRequestId}. Creation/refresh may enqueue existing AI run; source table/calculation is usable immediately, narrative pending is explicit.
1. Settle structured brief: decision title/goal; five measures with targets/cost/lag; model result; who benefits and who remains underserved; verified advantages/concessions; critical indicators; tested assumptions and remaining limits; compared alternatives/selection rationale; source/rules/evaluator IDs. Numerical fields come from evaluation refs, not editable invented numbers.
2. Generate through real tools/context from exact selected revision, constraints, comparisons, stress and user's existing rationale. `writeBrief({sourceRevisionId,stressId?,comparisonIds?,sectionDrafts})` validates ownership/provenance/quality and persists. `readBrief({briefId})` supplies current sections/edits. `updateBrief({briefId,expectedVersion,sectionPatches})` respects edit intent and preserves unselected sections.
3. Domain prompt procedure: build a concise recommendation supported by the chosen portfolio; include what it sacrifices, where the model remains weak and which assumptions were tested; treat stakeholder assertions in user notes as user context, not verified effects. Use same numerical/evidence gates as01. Do not call a constrained result globally best or a sensitivity repair official baseline optimum.
4. Render a readable document with inline evidence drilldowns and an edit mode for narrative sections, title and rationale. Provide section-targeted «Уточнить» using selected section/version, plus manual save. User notes labelled as authored rationale when they differ from generated analysis; never silently make them validated model facts.
5. Refresh after changed scenario keeps prior brief intact as historical and creates/updates an explicit new version. Preserve user-edited prose, refresh numeric refs/unchanged generated sections, flag edited sections whose referenced premise changed and offer compare/replace. New derivative is current only after source alignment. Export of historical brief remains possible with its old source visibly labelled; no mixed-version current brief.
6. Presentation route uses this actual brief in compact slides/sections: choices, district consequences, tradeoff, sensitivity, final rationale. Keyboard next/previous and all-in-one readable mode; no separate LLM numbers. Print style is genuinely useful and suppresses controls while preserving sources/labels.
States: pending explanation leaves calculated table usable; failed provider preserves user text/table and offers retry; stale source/409 identifies which version changed. All editor actions/labels/statuses localized; generated language follows request; interface switch never retranslates user prose.
Acceptance: V5 user changes rationale then stress/revision refresh; edited prose survives, outdated premises flagged, evidence links match selected revision. Two-owner access denied incl tool section update. Invalid/stale evidence blocks ready status. Actual model generates one brief from real chosen portfolio; inspect factual support rather than fluent text alone.

## 03.2 Persistent export artifacts and deletion
Outcome: user downloads the current or explicitly chosen historical artifact and can use it outside the app; all files survive restart and remain private.
Paths: src/server/city/{exports.ts,artifact-access.ts,cleanup.ts}; src/features/city/brief/render.ts; /api/city/artifacts/; storage adapter only if a confirmed requirement is missing; worker task handlers; schema/migrations/messages; local/production volumes already prepared.
Entity city_artifacts per C6 plus export/deletion jobs. API POST /artifacts {briefId?,revisionId,briefVersion?,kind:html|json|csv,locale,clientMutationId}; GET /artifacts/:id; GET /artifacts/:id/download; DELETE /artifacts/:id. Brief HTML requires actual saved brief/source match; JSON/CSV can export a saved valid scenario without AI. Incomplete draft JSON may be supported only if explicitly marked draft/no official Score; never presentation-ready by default.
1. Produce three truthful formats from stored source: self-contained UTF-8 HTML brief with print stylesheet; JSON typed scenario including dataset/rules/hash, decisions,constraints,evaluation and optional stress/provenance; CSV five measures/targets/cost/lag and necessary indicator/source table sections or explicitly named separate table. Stable units/localized headings, numerical representations documented. No need to build arbitrary external uploads/importer.
2. HTML preserves generated/user text and evidence/source summary with no executable script or remote asset requests. Include local embedded font only within10MiB budget or readable system fallback. Download as attachment; preview inside restrictive sandbox/CSP. Browser print gives PDF with actual title, wrapping and page breaks; do not claim server PDF generation.
3. Export handler inserts pending metadata idempotently, generates bounded bytes, records intended checksum/key, puts through common storage, verifies head/bytes as needed and atomically marks ready. If DB finalization fails after upload, tracked pending row lets retry reuse or safely delete exact object. Ready only means both metadata and bytes verified; failure retains source and retry action.
4. Download resolves principal, artifact ready state, parent visibility and immutable source; stream/proxy authorized bytes with safe filename, MIME, no-store and nosniff. A raw object key or another user's artifactId must not grant access. Rate guard only protects repeated generation, not ordinary retrieval.
5. Implement deletion worker jobs shared with scenario deletion/guest expiry: revoke access before cleanup, delete exact object idempotently, mark deletion complete, then remove eligible records. Preserve backend/key tombstone on errors and bounded backoff. Same worker scans due tracked pending>24h and expired guests periodically; no user-notification automation/watchers.
6. Retention shown in library/account claim path. Local/R2 behave identically for export/download/delete; R2 missing uses persistent local volume, partial config and outage stay truthful. Do not provision a new bucket/public access or leak signed URLs in logs.
States: generation progress reflects actual phases; board/brief remains editable; source version displayed on finished file; editing source creates a new file identity instead of replacing immutable bytes. Failure shows retry and keeps existing successful downloads.
Acceptance: compare exported values/text/source IDs to stored revision and user edits; JSON re-parses; CSV protects formula-like user text and handles ru/kk/en; HTML escaped script payload cannot execute. V7 local write→container replacement→read checksum; delete→new download denied→cleanup completed. When R2 configured, write/read/delete a uniquely named owned test object and remove only that object; never call R2 verified from local tests. Simulate put failure and DB-finalize retry without duplicate/orphan success.
Commit: integrated export/cleanup capability. No large base64 files in DB or accidental public bucket links.

## 03.3 Revocable snapshots and team comparison
Outcome: a team can share a frozen decision for discussion and compare up to3 compatible team proposals without exposing private workspace/history.
Paths: src/server/city/{shares.ts,comparisons.ts}; src/app/[locale]/share/[token]/page.tsx; src/features/city/components/sharing/; /api/city/shares/; schema/migrations/messages.
Entity city_shares {id,ownerId,tokenHash,scenarioId,revisionId,briefId/version?,artifactIds[],expiresAt,revokedAt,createdAt}. API POST /shares {revisionId,briefId?,briefVersion?,artifactIds[],clientMutationId}; GET /shares (owner list metadata); DELETE /shares/:id; public GET /shares/view/:token and /shares/view/:token/artifacts/:artifactId; POST /comparisons/shared {shareTokens:[1..3]}.
1. Explicit share action shows which frozen revision/brief/files become accessible and default expiry30days, then creates link. No approval dialog on unrelated edits. Token random>=256bits, stored hash; generate/get link on creation response only. Owner list can revoke/create replacement instead of recovering plaintext tokens. Team display name is owner-entered bounded text, not a fabricated account endorsement.
2. Public page reads only selected snapshot projection: title/decisions/model result/approved brief sections/source assumptions/files. Never expose owner email, private prompts, history, other candidates or internal receipts. Set noindex and no-store, Referrer-Policy no-referrer, no third-party assets/analytics that receive token. Guest/account owner follows same rules.
3. Shared comparison accepts pasted app share links/tokens, parses locally/server validation to known token format and queries DB directly. Never fetch arbitrary user URL (avoid SSRF). Limit3 snapshots; enforce identical dataset/rules/evaluator policy and official vs sensitivity grouping. If incomparable, explain mismatch and offer separate inspection rather than misleading rank.
4. Render budget, Score/components, district differences, direct vs city effects and decisions; use public snapshot service with exact permitted fields, not private comparison bypass. Sharing a stress result labels it explicitly; it cannot enter normal official comparison. An owner may fork an accessible shared decisions snapshot into their own scenario via deliberate action, assigning new owner and source attribution without copying private run history.
5. Revoke/expiry applies to every new data/file request; share download uses authorized app proxy, not long-lived signed URL. Already downloaded bytes cannot be recalled; do not promise otherwise. Parent deletion invalidates link immediately. Existing owner UI update hides/relabels stale links without page refresh.
6. Changes after publication create private later versions; only explicit new share publishes them. User can see snapshot revision in list/detail and distinguish current vs shared work. If compared link is revoked mid-use, remove its access/results on next fetch and show useful error.
States: loading/expired/revoked/not-found share views are localized and do not reveal private metadata; copy action confirms actual clipboard success with selectable-link fallback. Mobile comparisons remain readable and operable. Public locale may change labels, not authored brief content.
Acceptance: V7 cross-owner/private denial, successful intended public read, incompatible dataset/sensitivity rejection, revoke denies page-data/download, token not in logs, post-share private edit not visible, deleting original invalidates all derived links. Fork owns only public data and preserves attribution. Test with real distinct owners, not hidden controls alone.
